# 팀원 작업 통합 — 2026-11-15

기준: feat/team1-demo-session e7d8732. driving-ui/yoonseo-ui의 공통 주행 UI와 feat/state-storage-validation의 데이터 로직을 필요한 부분만 통합했다. 기존 첫 만남, 이름, 시연 저장 격리, 실제 SDK 누적 거리 패널, 새 출발 그림, Android 창 대응은 보존했다.

## 화면 연결
- S2 정상 출발: 기존 안전벨트 아기 토토 유지.
- S3 49km 또는 시연 설정 > 연료 부족: 팀원 hungry PNG와 한 줄 안내.
- 시연 설정 > 타이어 경고: hurt PNG.
- 시연 설정 > 노란 경고: worried PNG.
- 시연 설정 > 빨간 경고: 얼굴/캐릭터/지도/꾸미기 숨김, 차량 경고를 확인하고 안전한 곳에 정차하라는 안내. P/D 모두 상호작용 차단.
- 시연 설정 > 내 방 또는 내 토토로 돌아가기: 모의 경고를 해제하고 복귀. 기존 저장본에 경고필드가 없어도 시연 경고가 남지 않도록 baseline과 합쳐 복원.
- 150km 미만 배고픔, 50km 미만 연료 부족은 팀원 임시 시연 기준. 실제 진단 임계치가 아니다.

## 데이터 연결
- pendingGrowthStage 저장 및 기존 상태 마이그레이션, 현재 ODO가 미수신이어도 이미 보류된 성장 단계 유지.
- 거리0·trip0에서 D 전환만으로 배지 지급하지 않음. trip의 상태와 범위도 검증.
- 사용 제한 또는 빨간 경고 중 거리/회복/배지/성장 이벤트 반영 보류.
- 해제 시 현재 모의 ODO를 반영하고 성장 이벤트는 주차 후 확인. 중복 입력에도 이벤트 중복 없음.
- 실제 SDK 값은 독립 패널만 갱신. 위 warning/gear/range/성장 데이터는 모의다.

## 검증과 제한
실제 HMI module의 최소 DOM adapter로 3개 이미지 경로·경고 우선순위·P 차단·기존 상태 복원 검사. 상태 엔진의 제한/경고 보류·해제 적립·이벤트 중복·저장 복원 회귀 검사.
이미지 3개는 팀원 GitHub의 기존 blob SHA를 그대로 재사용하여 파일을 포함한다. 커넥터의 바이너리 다운로드 제한으로 이 환경에서 원본 PNG를 육안 검수하지 못했다. 크롬에서 표시·비율 확인은 남아 있다.
실제 WebView/크롬 실행과 warning SDK 실수신은 미검증이며 실제 차량 경고 연동을 주장하지 않는다.

## 크롬 확인
브랜치를 pull하고 기존 http.server를 유지한 뒤 강력 새로고침한다. http://localhost:8080/?android=1 에서 시연 설정을 열고 S1~S5와 새 경고 버튼을 확인한다. 각 경고 후 내 토토로 돌아가기로 저장 상태가 복원되는지 확인한다. SDK는 크롬에서 연결되지 않는다.
