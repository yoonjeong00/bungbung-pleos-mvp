## 1. 파일별 역할

| 파일 | 하는 일 |
| --- | --- |
| [`dist/js/logic.js`](../dist/js/logic.js) | **앱의 기억 장치이자 판단 기준.** 차 데이터를 보고 "지금 주행 중인지, 화면을 막아야 하는지, 몇 km 같이 달렸는지, 몇 단계인지"를 계산한다(`derive`). 토토 정보를 휴대폰에 저장하고(`save`) 다시 읽어 온다(`load`) |
| [`dist/js/state-machine.js`](../dist/js/state-machine.js) | **일이 일어나는 순서 관리자.** 주유하면 회복 장면, 거리가 차면 성장 장면을 예약해 뒀다가 주차했을 때 하나씩 꺼내 보여준다(`advance`, `takeEvent`, `completeEvent`). 배지와 보상(밥그릇·목도리)도 여기서 준다 |
| [`dist/js/demo-session.js`](../dist/js/demo-session.js) | **시연 칸막이.** 시연 패널로 무엇을 눌러도 진짜 저장된 토토가 바뀌지 않게 막는다. 같은 내용은 다시 저장하지 않는다 (팀원1 작성) |
| [`dist/js/vehicle.js`](../dist/js/vehicle.js) | 가짜 차 데이터를 만들고, 범위 밖 숫자나 모르는 기어 같은 이상한 값을 걸러 낸다. 기준값 상수 `FUEL_THRESHOLDS`, `TEMP_THRESHOLDS`가 여기 있다 |

### 저장 구조
- 모든 정보는 휴대폰 저장소의 **`bungbung-v1` 이름표 하나**에 저장된다. 이름, 단계, 배지, 소품, 함께 달린 거리, 기다리는 장면, 마지막 차 데이터가 다 들어 있다.
- 쓰기: 화면 코드가 `session.checkpoint(s)`를 부르고, 시연 중이 아닐 때만 `save`가 실제로 저장한다.
- 읽기: `load`가 저장값을 항목마다 검사하고, 옛 버전 형식이면 지금 형식으로 바꿔서 돌려준다.

## 2. 고칠 때 조심할 곳

| 위치 | 하는 일 | 잘못 고치면 |
| --- | --- | --- |
| **저장 이름표 `bungbung-v1`** (`logic.js`의 `load`·`save`) | 저장 상자의 이름 | **모든 사용자의 토토가 사라진 것처럼 보인다.** 이름·단계·배지가 처음으로 돌아가고 첫 만남부터 다시 시작한다. 예전 데이터는 남지만 아무도 읽지 못한다 |
| **옛 저장 데이터 변환** (`logic.js`의 `load`) | 예전 버전 저장 내용을 지금 형식으로 바꿔 읽는다. 예: 첫 만남 기능이 생기기 전 사용자는 "이미 만난 것"으로 처리, 대기 중이던 성장 장면 유지 | 이 부분을 지우거나 바꾸면 **기존 사용자에게 첫 만남 화면이 다시 뜨거나**, 진행 중이던 성장 장면이 사라진다 |
| **허용 목록** (`logic.js`의 `badgeIds`, `itemIds`, 모자 목록) | 저장값을 읽을 때 목록에 있는 것만 받아들인다 | **새 배지·소품을 만들고 목록에 안 넣으면, 받은 배지가 앱을 다시 열 때 사라진다.** 예: "1만 km의 추억" 배지를 구현할 때 `badgeIds`에 꼭 같이 넣는다 |
| **새 저장 항목 추가** (`logic.js`의 `initial`과 `load`) | 저장할 값의 기본값과 읽기 규칙 | `initial`에만 넣고 `load`에 안 넣으면 저장은 되지만 **앱을 다시 열 때마다 기본값으로 돌아간다** |
| **성장 계산** (`logic.js`의 `derive`, `stageForDistance`) | 함께 달린 거리 = 지금 ODO − 부화 기준 ODO. 가장 컸던 값(`maxDistanceKm`)을 기억해 줄지 않게 한다. 제한·빨간 경고 중에는 멈췄다가 풀리면 반영한다. 거리 → 단계는 `stageForDistance`가 단계 목록(`stages`)의 거리만 보고 **지나온 마지막 단계**를 돌려준다(0km·모르는 거리는 1 아기, 알 0은 돌려주지 않음). 화면 계산(`derive`)과 옛 저장값 변환(`load`)이 모두 이 함수를 쓴다 | 함수를 바꾸면 **화면과 옛 저장 데이터 읽기가 함께 바뀐다.** 단계 목록 `stages`의 0번이 "알"이라 0부터 세면 새 사용자가 "알"로 보인다. 한번 오른 단계(`ackStage`)와 받은 "첫 성장" 배지는 되돌릴 수 없다 |
| **단계 목록 `stages`와 최고 단계** (`logic.js`의 `stages`, `MAX_STAGE`) | 성장 기준 거리(300/2,000/6,000km)는 이 목록에만 있다. 최고 단계 `MAX_STAGE`는 **목록 길이로 정해진다**(`stages.length - 1`, 지금 4 = 어른). `load`는 저장된 단계를 1~`MAX_STAGE`로 맞춰 읽는다 | **`stages` 목록에는 단계만 넣는다(최고 단계가 목록 길이로 정해짐).** 단계가 아닌 것을 넣으면 최고 단계가 같이 늘어난다. 단계를 줄이면 그보다 높게 저장된 사용자가 내려간 단계로 읽힌다. 단계를 추가·삭제할 때는 단계 그림(`stage1~4.webp`)과 성장 기록 화면도 같이 맞춘다 |
| **부화 기준 ODO** (`baseOdo`, 지금은 10,000 고정) | 성장 거리의 출발점 | **실제 ODO를 연결할 때 가장 위험하다.** 실제 ODO가 45,000km인 차에 그대로 연결하면 35,000km를 달린 것으로 계산돼 **바로 어른이 된다.** 실제 ODO 연결은 부화 때 실제 ODO 저장과 반드시 함께 한다 |
| **회복 판정** (`state-machine.js`의 `advance`) | 주행 가능 거리 50km 미만을 본 뒤 100km 이상 늘면 회복 장면, 배부른 날 배지, 밥그릇 | 받은 배지와 소품은 저장돼 되돌릴 수 없다. 조건을 느슨하게 하면 **엉뚱할 때 배지가 생긴다** |
| **장면 순서** (`state-machine.js`의 `takeEvent`, `completeEvent`) | 장면은 주차 중에만 하나씩 꺼낸다 | 순서를 바꾸면 **주행 중에 성장 장면이 뜨거나**(기준서 위반) 장면이 사라진다 |
| **화면을 막는 판단** (`logic.js`의 `derive` 제한 조건, `signalValid`) | 신호가 없거나 오래됐거나 이상하면 화면을 막는다 | 느슨하게 하면 **주행 중 안전 규칙을 어길 수 있다** |
| **시연 칸막이** (`session.checkpoint`) | 시연 중에는 진짜 저장을 하지 않는다 | `save`를 직접 부르면 **시연 값(예: 2,180km, 청소년)이 진짜 토토에 덮어써진다** |

### 3.2 테스트가 못 잡는 것
- **저장 이름표 변경**: 이름표를 글자로 확인하는 테스트는 `hmi-integration.mjs` 하나뿐이다. 나머지는 코드가 쓰는 이름표를 그대로 따라가므로 이름표를 바꿔도 통과한다.
- **기준값 변경의 의도**: [`tests/thresholds.mjs`](../tests/thresholds.mjs)가 지금 기준값(연료 50/150km, 주유 감지 100km·10초, 기온 3/30°, 성장 300/2,000/6,000km)과 경계(49/50km, 1,999/2,000km 등), 회복 판정과 `load`의 연료 부족 기록을 검사한다. `logic.js`·`state-machine.js`는 이제 숫자 대신 `FUEL_THRESHOLDS`를 쓰므로 둘이 어긋나지 않는다. 다만 기준값을 **일부러 바꾸면** 이 테스트가 실패하니, 기준서를 먼저 고치고 테스트의 기대값도 함께 바꾼다. 테스트는 "값이 바뀌었다"만 알려 주고, 그 값이 맞는지는 판단하지 못한다.
- **허용 목록 누락**: 새 배지를 만들고 허용 목록에 넣지 않는 실수는 그 배지를 저장·다시 읽는 테스트를 따로 만들어야 잡힌다.
- **진짜 기기 저장소**: 테스트는 가짜 저장소를 쓴다. 실제 차 WebView의 저장 동작, 앱 업데이트 뒤 데이터 유지, 저장 공간 부족은 확인하지 못한다.
- **진짜 옛 데이터**: 옛 저장 데이터는 손으로 만든 샘플 몇 개만 검사한다.
- **실제 차 데이터**: 모두 가짜 값이다. 실제 단위(m/km), 수신 간격, 실제 ODO 크기는 확인하지 못한다.
- **오랜 기간 사용**: 몇 달 동안 쓰거나 날짜가 바뀌는 상황은 검사하지 않는다.
- **화면 모양**: 화면에 글자가 들어 있는지만 본다. 실제로 어떻게 보이는지는 확인하지 않는다.

### 3.3 고치기 전에 추가하면 좋은 테스트
- 기준값 경계: 49km는 연료 부족, 50km는 아님 / 1,999km는 어린이, 2,000km는 청소년
- 새 배지·소품을 만들 때: 얻기 → 저장 → 다시 읽기 → 남아 있는지

## 4. 작업 규칙 요약
- 저장 이름표(`bungbung-v1`)와 옛 저장 데이터 변환(`load`)은 고치기 전에 무엇이 바뀌는지 설명하고 확인받는다.
- 새 배지·소품·저장 항목을 만들면 허용 목록과 `load`·`initial`에 같이 넣는다.
- 저장은 반드시 `session.checkpoint`를 거친다. `save`를 직접 부르지 않는다.
- 남은 코드 작업과 위험도는 [SERVICE_SPEC.md](SERVICE_SPEC.md) 13.3을 본다.
