## 1. 서비스 개요

| 항목 | 내용 |
| --- | --- |
| 서비스 이름 | **마이카펫 (My Car Pet)** |
| 캐릭터 이름 | **토토** (사용자가 첫 만남에서 이름을 바꿀 수 있음) |
| 내부 코드 이름 | `bungbung` (저장 이름표 `bungbung-v1`, 앱 ID `com.hipnote.bungbung`, 저장소 `bungbung-pleos-mvp`). **사용자에게 보이지 않으므로 바꾸지 않는다.** 저장 이름표를 바꾸면 기존 데이터를 못 읽고, 앱 ID는 출시 후 바꿀 수 없다. |
| 플랫폼 | Hyundai Pleos Connect (Android Automotive). 웹 화면(`dist/`)을 Android WebView로 감싼 구조 |
| 한 줄 정의 | 차 상태가 토토의 표정이 되고, 실제로 돌봐야 회복하며, 함께 달린 만큼 자라는 차량 동행 앱 |
| 대상 사용자 | `[결정 필요]` 예: 출퇴근 운전자 / 첫 차를 산 사람. 성장 속도와 보상 설계의 기준이 된다 |

### 핵심 루프
달리면 자라고(②) → 차에 문제가 생기면 토토가 아파서 돌보게 되고(①) → 멈추면 그 결과를 보며 함께 논다(③).

| 구분 | 기능 | 사용자 가치 | 동작 |
| --- | --- | --- | --- |
| ① 돌보기 | 차량 상태 안내 | 차가 보내는 신호를 놓치지 않는다 | 연료·경고·날씨를 토토의 표정과 쉬운 말로 알리고, 주유·정비하면 회복 |
| ② 자라기 | 주행 거리 성장 | 차를 탈수록 정이 든다 | 누적 주행 거리로 4단계 성장 |
| ③ 함께 놀기 | 주차 중 상호작용·꾸미기 | 멈춘 시간이 즐거워진다 | 기어 P에서만 방·옷장·배지·성장 기록 |

모든 기능은 **사용자 입력 없이 차량 데이터로** 동작한다.

## 2. 용어

| 용어 | 뜻 |
| --- | --- |
| 주행 중 | 기어 D/R/N. **신호 대기(D, 속도 0)도 주행 중**이다 |
| 주차 | 기어 P. 불명확하면 주차로 추정하지 않는다 |
| 제한 상태 | 주행 제한 신호(`uxRestricted`)를 못 받았거나, 연결이 끊겼거나, 백그라운드인 상태. 토토 UI와 안내를 시작하지 않는다. 백그라운드: 목표 · 미구현 (현재: 백그라운드는 정차 연출만 멈추고 화면 판단에는 쓰지 않음) |
| 유효 정보 | 출처·값·단위·수신 시각·지원 여부 검증을 통과한 데이터 |
| DO (운전 중 사용 가능 앱) | 운전 방해를 최소화하도록 설계했다고 신고한 앱. 신고하지 않으면 주행 중 사용할 수 없다 |
| 모의 데이터 | 실제 차 대신 시연 패널이나 ADB로 넣는 가상 값. 화면에 항상 표시한다 |

## 3. 화면 구조

### 3.1 차 상태별 화면

| 차 상태 | 판단 기준 | 오른쪽 창 (마이카펫) |
| --- | --- | --- |
| 제한·불명 | `uxRestricted` 미수신, 연결 끊김, 백그라운드 | 토토·안내를 시작하지 않음. 백그라운드: 목표 · 미구현 (현재: 정차 연출만 멈춤) |
| 주행 중 | 기어 D/R/N (신호 대기 포함) | 주행 화면: 토토 정지 이미지 + 상태 표시 + 숫자 + 한 줄 대사 |
| 위험 경고 | 빨간 등급 경고 발생 | 토토 숨김. 오른쪽 창 전체를 경고 안내 화면으로 덮음 (5.3) |
| 주차 중 | 기어 P | 정차 화면: 내 방·성장 기록·배지 도감·꾸미기 |
| 시동 OFF 직전 | P + 시동 OFF | 하루 마무리 요약. 목표 · 미구현 (현재: 시동이 ON이 아니면 잠금 화면 "차량 상태를 확인하고 있어요". 하루 마무리는 시연 S10·화면 바로 보기에서만 열림) |

- 기어가 P가 아니게 되면 정차 화면은 **즉시** 닫히고, 다시 열 때 자동 재생하지 않는다.
- 판단이 불명확하면 항상 더 제한적인 쪽을 고른다.

### 3.2 주행 화면 배치

| 모드 | 화면 | 비고 |
| --- | --- | --- |
| 시연용 (1920×1080) | 왼쪽 차량 상태 · 가운데 가상 내비 · **오른쪽 마이카펫** | 왼쪽·가운데는 고정 그림. 바뀌는 건 오른쪽 창뿐 |
| 앱 모드 (`?android=1`, 1280×720 기준) | 마이카펫 창만 | 실제 차에서 보이는 모습 |

오른쪽 창 구성:
- 위 왼쪽: 작은 얼굴 아이콘 + "마이카펫" (빨간 경고 때는 얼굴 아이콘과 이름을 포함해 오른쪽 창 전체를 경고 안내 화면이 덮음)
- 위 오른쪽: 상태 표시 1개
- 가운데: 기본·신호 대기는 창 너비를 채우는 사진 카드, 상황별 토토는 창 가운데
- 숫자: 주행 가능 거리(km), 바깥 기온(°). **대사보다 크게**
- 아래 카드: 상태 아이콘 + 한 줄 대사
- 구석: "모의 데이터" 표시

### 3.3 디스플레이 대응

| 디스플레이 | 주행 중 | 주차 중 |
| --- | --- | --- |
| Connect-S (일반형) | 내비와 1:1 | 가로 전체 |
| Connect-W (와이드형) | 보조 창 (2:1 중 1) | 기본 창 가로 |

창 크기·방향이 바뀌어도 잘리거나 겹치지 않아야 한다. 여러 안내가 와도 자동 슬라이드·연속 팝업 없이 대표 카드 1개만 보여준다.

## 4. 핵심 기능 ① 차량 상태 안내

### 4.1 경고 단계별 역할

| 단계 | 예시 | 차량 시스템 | 토토 (주행 중) | 토토 (주차 후, P1) |
| --- | --- | --- | --- | --- |
| 관리 필요 | 연료 부족 | – | 정지 이미지 + 한 줄 | 근처 주유소 안내 |
| 주의 | 타이어 공기압 낮음 | 노란 경고등 | 정지 이미지 + 한 줄 | 쉬운 설명 + 근처 정비소 |
| 위험 | 브레이크·엔진오일·냉각수 | 빨간 경고등 + 경고음 | 숨음 (시스템 우선) | 쉬운 설명 + 정비 예약 연결 |

### 4.2 원칙
- 지원되지 않거나 값이 없는 항목은 0이나 정상으로 표시하지 않고 **숨긴다**.
- 표정만으로 의미를 전하지 않는다. **항상 글자와 숫자를 함께** 보여준다.
- 데이터로 확인되지 않는 추론을 하지 않는다. (예: 외기온이 높다고 "엔진 과열", 와이퍼로 "노면 미끄러움"이라고 하지 않는다. 결빙·미끄럼 경고는 차량 시스템 몫이다.)
- 같은 이벤트를 반복 안내하지 않는다 (앱 재실행·화면 전환·같은 값 재수신 포함).
- 생성형 AI가 문구를 만들지 않는다. 승인된 문구 목록으로만 안내한다.

## 5. 토토 상황표 (주행 중)

### 5.1 상황별 정의

| 상황 | 조건 | 토토 이미지 | 상태 표시 | 대사 |
| --- | --- | --- | --- | --- |
| 빨간 경고 | `safetyWarnings`에 빨간 등급 | 숨김 | – | – (5.3 경고 안내 화면) |
| 연료 부족 | `rangeRemainingKm` < 50 | `bungbung_child_hungry.png` (전용 이미지 제작 예정) | 연료 부족 | 배고파… 주유소 들를까? |
| 타이어 경고 | `tireWarning` = true | `bungbung_child_hurt.png` | 타이어 확인 필요 | 발이 좀 아파… 타이어 봐줄래? |
| 노란 경고 | `safetyWarnings`에 노란 등급 | `bungbung_child_worried.png` | 차량 알림 있음 | 차가 알려줄 게 있대요 |
| 주유 직후 | 주행 가능 거리가 100km 이상 늘어난 뒤 10초 | `bungbung_child_happy.png` | 주유 완료 | 배불러! 고마워요 |
| 배고픔 | 50 ≤ `rangeRemainingKm` < 150 | `bungbung_child_hungry.png` | 주행 가능 거리 | 주행 가능 ○○km |
| 추움 | `outsideTempC` ≤ 3 | `bungbung_child_cold.png` | 추운 날 | 코끝이 시려요 |
| 더움 | `outsideTempC` ≥ 30 | `bungbung_child_hot.png` | 더운 날 | 오늘 덥다~ |
| 비 | `wiperState` 작동 | `hmi-assets/extracted/rain.webp` (팀 주행 그림에서 잘라낸 비 장면, 코드 이름 `art('rain')`) | 와이퍼 작동 중 | 톡톡, 비가 와요 |
| 밤 | `headlightOn` = true | `bungbung_child_sleepy.png` | 밤 운전 중 | 별이 뜨는 밤이에요 |
| 신호 대기 | 기어 D, 속도 0 | 기본 사진 카드 | 신호 대기 · D | 잠시 멈췄어요 |
| 기본 | 위 조건 없음 | 기본 사진 카드 | 함께 달리는 중 | 오늘도 함께 달려요 |

- 기준값은 코드 상수 한곳에 모은다: `FUEL_THRESHOLDS`(배고픔 150km, 연료 부족 50km, 주유 감지 100km·10초), `TEMP_THRESHOLDS`(3°, 30°) — `dist/js/vehicle.js`. 정차 화면과 주유 회복 판단(`logic.js`)도 같은 상수를 써야 한다.
  - 현재(코드): 정차 화면과 주유 회복 판단은 상수를 쓰지 않고 숫자를 직접 쓴다. `logic.js`는 배고픔 판단(`range<50`)과 저장값 읽기(`lowRangeKm<50`) 두 곳에 50, `state-machine.js`는 연료 부족 기록(`n<50`)에 50, 회복 판단에 100km를 직접 쓴다. → 13.3 다음 코드 작업 N5·N6
- 상황별 이미지는 지금 **어린이 단계만** 있다. 다른 단계는 기본 이미지를 쓴다. `[결정 필요]` 단계별 상황 이미지를 만들지, 상황 표현은 어린이 디자인으로 통일할지

### 5.2 우선순위
여러 상황이 겹치면 **하나만** 보여준다.

빨간 경고 > 연료 부족 > 타이어 경고 > 노란 경고 > 주유 직후 > 배고픔 > 추움·더움 > 비 > 밤 > 신호 대기 > 기본

작은 효과(하트·눈송이·빗방울)는 이미지에 그리지 않고 코드로 얹는다. 주행 중에는 움직이지 않는다.

### 5.3 빨간 경고 화면
- 오른쪽 창 전체를 경고 안내 화면으로 덮는다. 시연용 3칸 화면에서 가운데 내비는 그대로 보인다.
- 안내 문구는 운전 지시 금지 규칙의 **예외**다. 토토의 대사가 아니라 시스템 안내 문구이기 때문이다. 현재(코드, `hmi-app.js`의 `criticalWarning`) 문구:

| 자리 | 문구 |
| --- | --- |
| 제목 | 차량 경고를 확인해 주세요 |
| 안내 | 안전한 곳에 정차하고 차량의 경고 안내를 따라 주세요. |
| 보조 | 캐릭터·꾸미기·성장 처리가 잠시 중단돼요 · 모의 경고 시연 |

## 6. 핵심 기능 ② 주행 거리 성장

### 6.1 성장 단계

| 단계 | 이름 | 함께 달린 거리 | 예상 도달 (일평균 37.8km 기준) | 해금 |
| --- | --- | --- | --- | --- |
| (연출) | 알 | 설치 직후 | 첫 만남에서 부화 | 이름 짓기 |
| 1 | 아기 | 0 ~ 300km | 설치 당일 | 기본 방 |
| 2 | 어린이 | 300 ~ 2,000km | 약 8일 | 옷장 |
| 3 | 청소년 | 2,000 ~ 6,000km | 약 2개월 | 방 꾸미기, 배지 도감 |
| 4 | 어른 | 6,000km 이상 | 약 5개월 | 특별 아이템 |

- **알은 성장 단계가 아니다.** 첫 만남 연출에서만 보이고 성장 기록에는 나오지 않는다. (코드에서는 0번 단계로 남아 있음)
- 기준 거리는 `dist/js/logic.js`의 값이다. 현재(코드): logic.js 안 **세 곳**에 따로 적혀 있다 — 단계 목록(`stages`), 단계 계산(`derive`), 옛 저장값 변환(`load`). → 한곳으로 모은다 (13.3 N7)
- 해금: 목표 · 미구현 (현재: 단계에 따른 잠금 없음. 옷장·배지 도감은 처음부터 열리고, 방 꾸미기는 "준비 중")
- 저장 데이터에는 단계 **번호**가 저장된다. 단계 이름을 바꿔도 기존 데이터에 영향이 없다.
- 단계 이미지: `dist/hmi-assets/extracted/stage1~4.webp`
- 어른 이후에는 1만 km, 2만 km마다 기념 배지가 쌓인다. 목표 · 미구현 (현재: "1만 km의 추억" 배지 칸만 있고 "준비 중")
- `[결정 필요]` 3단계 이후 간격이 길다(약 2개월 → 5개월). 그 사이를 채울 작은 보상(주간 배지, 계절 옷, 거리 기념일)을 설계한다.

### 6.2 계산
- 첫 만남(부화) 때 차의 누적 주행 거리(ODO)를 저장한다. 목표 · 미구현 (현재: 부화 기준 ODO는 10,000으로 고정)
- 앱이 열릴 때마다 현재 ODO를 읽는다. 백그라운드에 상주하지 않아도 거리가 빠지지 않는다. 목표 · 미구현 (현재: 성장은 모의 ODO로 계산. 실제 SDK 누적 거리는 별도 패널에만 표시하고 성장에 쓰지 않음)
- 성장 거리 = 현재 ODO − 부화 때 ODO. 지금까지 달린 가장 큰 값을 기억해 줄어들지 않는다.
- 빨간 경고나 제한 상태 동안은 성장 거리를 멈춰 두었다가, 해제되면 그동안 달린 거리를 한꺼번에 반영한다. 노란 경고·타이어 경고 때는 멈추지 않는다.

### 6.3 보여주는 방식

| 장면 | 표현 | 언제 |
| --- | --- | --- |
| 성장 게이지 | "어린이 · 다음 단계까지 420km" 막대 | 항상 (주행 중엔 숫자만). 목표 · 미구현 (현재: 정차 화면 "다음 성장까지 ○km" 막대, 주행 중에는 "성장 단계: ○○" 글자만) |
| 따라잡기 | "그동안 180km 같이 달렸네!" | 앱을 열었을 때 거리가 늘어 있으면 (주차 중). 목표 · 미구현 (현재: 없음) |
| 성장 장면 | 다음 단계 모습으로 바뀌는 연출 | 단계가 오른 뒤 **처음 주차했을 때**. 주행 중에는 미룸 |
| 성장 기록 | 단계별 카드와 도달 날짜 | 주차 중. 도달 날짜: 목표 · 미구현 (현재: 단계 카드와 거리만, 날짜 없음) |

### 6.4 저장하는 값 (최소)
부화 때 ODO, 현재 단계, 아팠던 동안 모은 거리, 획득한 아이템·배지, 토토 이름. 프로필·위치 이력·상세 주행 로그는 저장하지 않는다.

목표 · 미구현 (현재: 위 값 외에 최근 모의 차량 값 전체 1개(`vehicleSnapshot`), 함께 달린 최대 거리, 성장·회복 이벤트 대기열, 배지 획득 시각, 주유 전후 거리도 저장)

## 7. 핵심 기능 ③ 주차 중 상호작용·꾸미기

### 7.1 기준
- 기어 P일 때만 열린다. 신호 대기는 주행 중이다.
- 기어가 바뀌거나 제한 상태가 되면 즉시 닫히고 자동 저장한다.

### 7.2 기능

| 기능 | 내용 | 우선 | 현재 (코드) |
| --- | --- | --- | --- |

| 터치 반응 | 토토를 누르면 반응하고 지금 상태를 한 줄로 말함 | P0 | 구현. 1.6초 말풍선 "함께 쉬니까 기분이 좋아요!" (주행 가능 거리 50km 미만이면 "배가 고파요. 주유가 필요해요!") |

### 7.4 게임 분류 위험 관리
- 꾸미기·터치·방 움직임은 기어 P에서만 동작한다.
- 앱의 중심은 차량 관리(①)로 두고 **모빌리티 서비스** 카테고리로 등록한다.
- 점수·경쟁·시간 제한 같은 게임 요소는 넣지 않는다. 아이템은 실제 주행·관리로만 얻는다.
