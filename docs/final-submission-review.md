## 구현 범위
**실제 SDK:** 누적 거리 READ 지원 조회·get/listener 수신·오류/시효 표시. SDK 값은 독립 패널만 갱신한다.
**모의:** 토토 성장 거리, 기어, 연료/회복 추정, 온도, 사용제한, S1~S10, 하루 요약.
**미구현:** 실제 CarUxRestrictions/기어/주유/Navi, 위험 경고 우선 처리 및 경고 중 거리 보류, 차량별 최초 ODO, 시동 OFF 자동 요약, 자동 온도착용, 실제 와이퍼·라이트, 성장 이력 앨범, time/mileage 배지, 의상/방 편집 및 캐릭터 착용 합성.
**미검증:** 최종 APK 빌드/설치, Android 키보드·연속 터치·전원/백그라운드 복귀, 실제 값 변경 이벤트, GPU 겹침·실측 지연.

## APK 및 설치 증거
이 환경에서 최종 APK를 생성하지 않았다. Mac에서 `bash scripts/install-mac.sh` 실행 후 산출 경로:
`~/StudioProjects/bungbung-pleos-mvp/android/app/build/outputs/apk/debug/app-debug.apk`
종류: debug 시연 APK. 스크립트가 HEAD를 versionName/UI r5에 넣고 설치하며 SHA256·설치 버전·로그를 출력한다. 로컬 수정이 있으면 dirty 표시. 이 APK를 정식 배포 서명본이라고 부르지 않는다. 제출처가 요구하는 APK 종류와 서명을 확인할 것.

## 3~5분 시연 순서
1. SDK 패널(30초): READ 및 실제 누적 거리, 다른 게임 값은 모의임 설명. 가능한 경우 정상 차량 데이터 콘솔에서 ODO 변경 후 값 변경 카운터/숫자 갱신 제시.
2. S1 첫 만남(40초): 이름 입력→시작→내 방. 신규 사용자 가치와 버튼 반응 제시.
3. S2 출발(30초): 정지 일러스트·한 줄 메시지, 방 꾸미기 조작이 사라짐.
4. S3 부족→S4 회복(40초): 49km 안내→주차 회복 카드→확인. 실제 주유 연동이 아닌 모의 추정임 설명.
5. S5 성장(30초): 300km 성장→확인→방 단계 확인. 반복 입력으로 중복 보상 없음.
6. S8 제한 신호 없음(20초): 제한 화면 제시.
7. S10 하루 마무리(30초): 거리·시간→확인→내 방. 필요 시 시연 설정의 내 토토로 돌아가기로 원본 복원.

`python3 scripts/simulate-android.py --tour`는 Enter마다 S1~S10을 보낸다. 터미널 Success만 보고 넘기지 말고 각 앱 화면에서 실제 버튼을 눌러 결과를 확인한다. S6~S10은 독립 모의 fixture이므로 순차 시연의 연속 주행 거리로 해석하지 않는다.

## 제출 직전 사용자 확인 (필수)
1. 최신 브랜치를 pull 후 install-mac 실행. UI r5의 커밋과 installed versionName 일치 확인.
2. S1 시작→S4 확인→S5 확인→S10 확인을 실제 클릭. 내 방/성장/옷장 각각 중복·잘림 확인.
3. SDK 실제 거리 입력 변경 전/후 화면 숫자 확인. 반복 알림만 증가하면 값 변경 검증 통과 아님.
4. 앱 재실행 후 이름/저장 유지, 전원·백그라운드 복귀 확인.
5. 실패 시 screenshot과 verify-submission-mac.sh 출력으로 원인 분리. 사용자 저장 데이터 초기화는 하지 않는다.
